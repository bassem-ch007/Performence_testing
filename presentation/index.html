CI — Continuous Integration

Checkout source, validate the new tag, build `linux/amd64`, authenticate to Docker Hub and publish a versioned image. CI should not interrupt running pods.

CD — Continuous Deployment

Replace the old image with the new one while Kubernetes controls pod replacement. Readiness checks protect service routing; monitoring verifies observed continuity.

Independent experiment Pipeline 05 first restores three healthy old product replicas, so its rollout does not depend on Stage 04 being run beforehand. Avoid running another stage during its build or deployment.
Presenter cue CI proves that a deployable artifact was built. CD proves that artifact was rolled into the cluster. Neither by itself proves zero downtime: that requires live client measurements.
